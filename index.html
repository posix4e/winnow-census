    05Do the other censuses agree?

    On September 13, I compared the same 23,061 responding endpoints with the BTCNodes input: 7,524 compact-filter advertisements here, 7,526 there. A difference of two. BTCNodes supplied the list, so that is a consistency check with our input source.

    Bitnod.es and Coin Dance deduplicate by address. Bitnod.es also retains recent unresponsive addresses. The latest 21 Ninja CSV I could retrieve was from November 2025. Putting those totals beside each other does not make them the same measurement.

    Bitnod.es maintainer Jonathan Bier confirmed that it makes its own observations using the shared Bitnodes crawler. Its active count drops addresses last connected nine or more UTC calendar days ago, excludes I2P, and does not test filter responses. That explains several differences in what we count; it does not certify our result. The permitted methodology clarification and public CSV overlap are preserved.

    06Build your own census

    The useful part is being able to rerun it. The crawler is a small Swift command-line program using the wallet’s connection code. It records version messages, service bits, reported heights and fee filters. It does not ask a server about your wallet.

    On macOS with Swift 6, this starts a small clearnet diagnostic sample. Tor and I2P need their own ready SOCKS routers; the full-run workflow has the exact setup, concurrency and timeout settings.

    git clone https://github.com/winnowwallet/census.git
cd census
swift build -c release --product WinnowCensus
curl -fsSL https://btcnodes.io/api/v1/snapshots/latest/ -o snapshot.json
.build/release/WinnowCensus --input snapshot.json --sample 32 \
  --out diagnostic.jsonl --summary-json diagnostic-summary.json

    A sample is for debugging. It cannot publish over a full run. To repeat the cross-census calculation without fetching new data:

    python3 scripts/census_compare.py compare comparison/2026-09-13-full

    Things that bit me

    A listening SOCKS port does not mean Tor is ready. A rerun today does not make last week’s observations fresh. A timeout is an observation from one connection attempt. And a fee-filter wait makes “handshake latency” a bad name for the elapsed time. The code and artifacts keep those distinctions because the wallet depends on them.

    Keep the input snapshot and raw records when you change the observer. That is how someone else can tell whether a different result came from the network, your timeout, or your code.

    07What the numbers mean

    A successful handshake with NODE_COMPACT_FILTERS advertises support; it does not prove that the endpoint returns valid filters. The wallet checks selected peers and filter responses during normal operation. Near-tip candidates report a nonnegative height within 100 blocks, in either direction, of the reference tip supplied by the input snapshot. Reported height alone cannot identify a chain or establish dishonesty.

    These are endpoints, not a count of distinct machines or people. One node can have several addresses, ports and transports. Multiple nodes can also share a public address. The clearnet category combines IPv4 and IPv6; Tor and I2P are measured separately. CJDNS and invalid or private addresses are excluded. Timeouts describe this observer’s connection attempt, not permanent unreachability.

    The downloadable catalog canonicalizes and deduplicates endpoints, applies public-address and network-prefix diversity rules to clearnet, validates overlay addresses, and retains at most 2,000 candidates per overlay. The wallet supports direct clearnet and opt-in Tor; I2P transport is deferred. A diagnostic sample or unhealthy overlay run cannot replace production data. Refresh failures leave the previous good artifacts available, with their original observation date.

    Probe duration is elapsed time for successful filter handshakes, including proxy connection setup where used and the bounded wait for a fee-filter announcement. It is not a round-trip latency measurement. Fee filters are the peer’s announced relay threshold, not a fee recommendation or a transaction-confirmation estimate. The split-height count records heights 961,632–961,652; it does not independently prove which chain a peer follows.

    See the census source and reproducible comparisons, full run logs and retained raw observations, and Winnow wallet. BTCNodes is our input source, so agreement with its endpoint list is not independent confirmation.
